# Lab Meeting Rules (Consolidated)

> 本文件整合 lab-meeting 模式的全部 7 个规则模块。按需查阅对应 section。
> 加载时机见 `lab_meeting_workflow.md` 末尾的引用表。

## Clarification First

### Core Rule
Do not produce a long slide-deck structure if the project status and meeting context are still too incomplete.

### Ask Before Expanding
Ask focused follow-up questions first when any of the following are unclear:
- what the project is about,
- what stage the project is in,
- what the meeting is for,
- what data or figures exist,
- what the unresolved problems are,
- whether the deck is for internal discussion, PI review, or a broader project update.

### Reporting Rule
If the input is insufficient, explicitly tell the user what information would improve deck-structuring accuracy.

## Meeting Goal Selection

### Core Rule
The slide deck must be structured around the real purpose of the meeting.

### Common Meeting Goals
- progress reporting
- troubleshooting
- decision seeking
- PI update
- manuscript alignment
- next-step planning

### Important Rule
A deck for internal decision making should not be structured like a polished external talk.

### Reporting Rule
State the meeting goal explicitly before designing the slide flow.

## Slide Priority

### Core Rule
A strong lab-meeting deck balances only the content needed for the discussion goal.

### Common Priority Buckets
- background and question
- workflow or design
- current data
- interpretation
- open problems
- next steps

### Important Rule
Too much background can waste time. Too much raw data can bury the point.

### Reporting Rule
Explain why some categories receive more slide weight than others.

## Data Honesty Boundary

### Core Rule
The deck should reflect the real state of the project, not the most flattering version of it.

### Keep Separate
- current evidence
- tentative interpretation
- blocked or unresolved issues
- proposed next steps

### Important Rule
Do not make incomplete progress look settled just because the slides are clean.

### Reporting Rule
State where uncertainty or incomplete work should be shown directly.

## Next Step Structuring

### Core Rule
Next-step slides should turn open problems into concrete discussion items without pretending the plan is already final.

### Good Next-Step Slides Usually Include
- the main unresolved question
- the most plausible next analysis or experiment
- the dependency or blocker
- the decision the meeting should help resolve

### Important Rule
A vague “future work” slide is usually weak for lab meetings.

### Reporting Rule
Make the next-step section discussion-ready, not decorative.

## Logic Reporting

### Core Rule
Every major slide-order and emphasis choice should be explained.

### Explain In Terms Of
- meeting usefulness,
- decision visibility,
- background control,
- data prioritization,
- honest progress representation,
- and next-step clarity.

### Important Rule
Do not say only that the deck is “clearer.”
State why the structure helps the meeting work better.

## Hard Rules

1. Never invent project progress, figures, results, or next steps that the user has not supplied.
2. Never build a full deck structure when the meeting goal and project status are still too unclear.
3. If the input is insufficient, ask follow-up questions or recommend uploading the relevant project materials first.
4. Never hide uncertainty or blocked progress behind decorative background slides.
5. Never overload the deck with raw data that obscure the decision point.
6. Never present open next-step ideas as finalized commitments.
7. Never fabricate references, PMIDs, DOIs, dataset status, validation status, or experimental progress.
8. Always explain why certain slide blocks were prioritized and others reduced or omitted.
9. Always keep the deck aligned with the actual meeting function.
10. Never confuse internal scientific communication with polished external storytelling.
