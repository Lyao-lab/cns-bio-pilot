# Deep Review Protocol — 深审查协议（语义验收 / 数字门）

> 来源：fetal_heart fig1-3 两轮深审查实战（2026-10-01 v2 + 2026-10-08 全链重算）。
> **定位**：视觉门（bigfig_deck_playbook E5）管"看得见的对"；本协议管"**语义的对**"——
> caption 数字是否真、结论是否被数据支撑、文献是否撑得住、口径是否声明。
> **什么时候跑**：deck/PPT 定稿前、投稿前、大改后、以及任何"我怀疑这些数字"的时刻。

## §1 五步审查（顺序执行，每步产出问题清单）

### 1. 数字全量溯源（逐声明对表/对 h5ad）
- 每个 caption/title/notes 里的定量声明 → 回溯到唯一计算表或 h5ad 实测（backed='r' 抽查）。
- **机检**：python-pptx 全文提取 → 与依据表逐数字比对；grep 已知旧值清单（见 §2）。
- 实例（本项目真实 catch）：谱系百分比标签错位（CM↔Mesen 数字互换）；donor 数 "3/窗" 实为 3/2/4/1/5；MYH6 区间混拼时点；DPT 中位数 0.33 → 重算 0.25。
- **不可复现 = P0**：两种口径都复现不出的历史数值（实例：VIC OXPHOS ρ=+0.87 / G2M -0.70），一律降级/删除并记录到台账。

### 2. 统计方法学审计
逐条问：n 的单位是什么（bin/细胞/供体/切片，分开报）？有 null/置换吗？校正族完整吗（多少检验做 BH）？校正后还显著吗（stats_convention 三层定措辞）？空间结论 n=1 切片了吗？
- 实例 catch：96 力学检验无 FDR（→ R3）；耦合 r 无检验（→ R1 block bootstrap）；"低应力→传导"与 Reckova 2003 反向（→ 降级为位置描述）。

### 3. 文献锚点红队（外部核查）
对每个"文献说/经典通路"主张分三级：**SUPPORTED**（引文方向一致）/ **TENSION**（与文献相反，必须重构措辞或补证据）/ **NOVEL**（本项目新观察，不得引为已知）。
- 实例：NRG1-ERBB4 经典是"促增殖/分化"而非"促成熟"→ 梯度改标"本队列新观察"；血流倍数为模型推导非文献值 → 图注加 "DERIVED"。
- 检不出≠失败：快翻转 TF 检不出是预期现象（图注说明反而堵审稿攻击点）。

### 4. 治理一致性
fig_tables：每个 panel 的依据表有唯一归档副本+manifest 行；散置 CSV 不作唯一副本。术语/单位/分箱口径全 deck 统一（GA 窗口、µm、q05、bins）。

### 5. 跨产物一致性
新旧 deck/INDEX/报告间 grep 陈旧数字与旧结论（`from pptx import Presentation` 全文提取 → 与"以表为准"清单比对）。同一数字在 caption/notes/标题三处不一致 = 单一数字源被破坏（回 §2 修复）。

## §2 数字门铁律（caption-from-table）

1. **caption/notes 的定量数字只允许从依据表读出**——禁止从对话记忆、prompt 转述、旧版 deck 抄写。派发任务时给数字仅作指引，**表与指引冲突以表为准**（实战：重建 agent 以表为准纠正了派发清单 3 处数字）。
2. 改数字 = 重跑 runner 写表 → 下游引用链更新（stats_convention §3）。
3. 每轮审查产出 `stale_numbers.csv`（旧值 → 新值 → 依据表 → 状态），下轮 grep 用。

## §3 版本切换纪律（注释/分群变更后）

注释列变更（如 cluster v3 → v4f）后：
1. **枚举依赖**：列出所有引用旧标签列的 panel/统计/表格（grep 旧标签字符串）。
2. **重算非重标**：所有簇依赖统计一律重算；旧簇专属实体名可能不存在于新参照（实例：coupling 里的 "FB_GPC6+" 不在 c2l 26 类 → 旧值不可移植，整句改写）。
3. **预期翻转**：以更严谨口径（donor-pseudobulk 替代 per-cell 校正 X）重算时，预期部分结论翻转（实例：5 保持/5 翻转——"NPPA 随 GA 下降"在 donor-pb 下不成立）。翻转是升级不是事故，如实进 deck 与台账。
4. 度量口径同时换的要显式声明（实例：比值口径在 z 尺度近零处不稳 → 改 Δ+CI，图注注明口径变更、与旧值不可直接比大小）。

## §4 口径声明律（每个统计量写清"什么×什么"）

任何相关/比例/倍数，deck 与 methods 必须能回答：**X 是什么、Y 是什么、在什么单元上算、怎么聚合**。
- 口径错位实例（本项目最大单笔发现）：面板 caption 写 "snRNA↔spatial ρ=0.80/0.17"，实际画的是**站内深度耦合**（bin counts × summed c2l q05）——图注错标。拆解后真跨模态一致 marker 级 ρ=0.78–0.83 三时点稳定（伪象翻卖点）。
- 多口径拆解模式：同一问题按 层级（marker/全基因/谱系/类型）、分辨率（bin50/100/200）、聚合（donor 均值/池化）分别报告，冲突的口径差异本身就是方法学发现。
- 单细胞特有陷阱：per-cell 校正表达 vs donor-pseudobulk 可给反向趋势（NPPA 实例）——组成性结论默认 donor-pb。

## §5 与其他门的关系

| 门 | 管什么 | 工具 |
|---|---|---|
| 像素门（E5） | 渲染层：截断/重叠/出界 | edge_sweep + visual-judge |
| 机检门 | 结构层：页数/图数/字号/md5 | `skills/presentation/scientific-slides/scripts/qa_deck.py` + `validate_presentation.py` + `scripts/edge_sweep.py` |
| **数字门（本协议）** | **语义层：数字真、结论撑、文献立** | 溯源表 + python-pptx grep + R1-R6 配方 |
三层全过才可外发。主智能体验收子任务交付时，数字门 = 对表抽检关键数字（不能只看汇报）。
