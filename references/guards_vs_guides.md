# Guards vs Guides — 护栏与指南的分界（Rule 0 展开版，2026-10-09）

> **定位**：本 skill 的规则体系分两层——**护栏（Guards）** 和 **指南（Guides）**。
> 用错了层次，先进模型会被规则捆死（过度合规、错过探索），或被自由带偏（翻车）。
> 本页是「规则怎么用」的元规则，与 SKILL.md Rule 0 互为表里。
> **谁读**：拿到本 skill 的第一步（任何任务），以及在「要不要破例」处停下时。

---

## §1 两层规则：护栏 vs 指南

| | **护栏（Guards）** | **指南（Guides）** |
|---|---|---|
| 本质 | 不变量——违反=出错 | 校准——按需采纳，偏离要说明理由 |
| 形态 | 「必须/禁止」+ 机检 | 「首选/参考/何时换」+ 决策表 |
| 违反的后果 | 结论错、科学错误 | 可能错过更优方案，不出错 |
| 冲突时 | 不可绕，写台账说明 | 可偏离，写台账说「偏了哪条、为什么」 |
| 例子 | pseudobulk DE、counts 先行、数字从表读、notebook 台账 | 选哪个聚类方法、面板怎么排、用几种 CCC 方法 |

**为什么必须分层**：把「选 STAGATE 还是 BANKSY」写成铁律，模型会在某数据上硬套错方法；把「pseudobulk DE」写成可选，模型会在某分析里忘了它。前者是过度束缚，后者是过度自由——两者都坏。

## §2 护栏清单（A 系 + E 系 数字门；违反=出错，无例外）

| 护栏 | 不变量 | 违反后果 | 机检 |
|---|---|---|---|
| **G1 诚实与溯源** | 每个数字/数据集/API 有来源；缺失标 `[AUTHOR TO SPECIFY]` | 虚构 = 造假 | postcheck F1 |
| **G2 单细胞 DE 必须 pseudobulk**（sample×celltype 聚合） | 统计单位=供体非细胞 | 假阳性膨胀 | postcheck D3/D4 |
| **G3 counts 层先行** | `layers['counts']` 在 QC 前拷贝 | DE/velocity 无法做 | postcheck A1 |
| **G4 校正后禁 DE** | corrected embedding ≠ raw counts | 疾病信号被抹除 | postcheck D3 |
| **G5 组成数据禁卡方/Fisher** | compositional 约束 | 统计错误 | postcheck C1 |
| **G6 口径声明 + 版本切换重算** | 注释变更后 grep 旧标签→重算非重标；旧值不可移植 | P0 语义错误（像素门查不出） | deep_review §1 |
| **G7 notebook 台账** | 代码落 ipynb（执行即登记） | 不可复现=没跑 | 验收查 notebook |
| **G8 机检门** | postcheck/qa_deck/validate/edge_sweep/数字门按产物各就其位 | 错误进交付物 | 机检脚本 |
| **G9 数字门（caption-from-table）** | 定量数字只从依据表读，表与指引冲突以表为准 | 手写数字漂移 | deep_review §2 |
| **G10 多样性/数据泄露**（machine-learning 类任务） | 训练/测试隔离、外部验证、泄漏排查 | 过拟合当发现 | 数据集审计 |

> 护栏之外的**一切方法选择**都不是护栏：用什么聚类、哪个 CCC 方法、画什么图、分几批跑——全是指南。

## §3 指南怎么用（用好自由度的四个动作）

1. **读决策表但不照抄**：`decision_guide.md` / `figure_guide.md` / `spatial_frontiers_2026.md` §1 / `paper_paradigms.md` 是「多数情况下该这样」的压缩经验——命中即用，命中不了就推理，别把表当唯一合法答案。
2. **首选池 + 何时换**：每个图型/方法条目都有「首选 / 何时换备选」——先按首选，数据不满足条件（n 太小、检验不成立、异常分布）时换备选，并在台账注明切换理由。
3. **平行多试**：拿不准时（新数据类型/新方法、参数敏感），**并行跑 2-3 个合理方案比结果**，而不是死守一个（SACCELERATOR 教训：参数变异可超方法变异）。比对结果本身就是发现。
4. **结果驱动**：跑一步看一步，结果推翻设计就改（Rule 8 Phase R 是其流程化）。指南支持探索：checkpoint + 台账让你敢试（随时可回滚）。

## §4 冲突与新情况（规则未覆盖时怎么办）

**优先级**：用户指令 > 数据证据 > 护栏。

1. **规则内部冲突**（少见）：护栏 vs 护栏——停下、写台账、问用户或给推荐项，不静默二选一。
2. **规则未覆盖**（常见，新平台/新方法）：回到第一性原理（G1-G10 的**精神**：统计单位对吗？重复独立吗？口径声明了吗？可复现吗？）——护栏不变量在新情境下怎么落，由你推理，落法写进台账供用户校准。
3. **用户指令与护栏冲突**（用户明确要求 per-cell DE）：先口头确认意图（可能是表述省略）；确认后按用户做，但在产物里加护栏 caveat（标注该步骤不符合 G2，结论措辞降级）。用户的知情权优先，不替用户硬把关到拒绝执行。

## §5 过度合规的反模式（先进模型常踩）

| 反模式 | 表现 | 纠正 |
|---|---|---|
| 规则堆砌 | 为每条规则都跑一遍，不管任务是否需要 | 护栏必过；指南按数据需要挑 |
| 唯一解执念 | 认为决策表只有唯一正确答案 | 命中即用、不中则推理、不确定则并行试 |
| 守门员心态 | 用户让做某事，因规则不许而拒绝/无限确认 | 护栏必守；护栏外给推荐+理由后执行 |
| 台账形式主义 | 每个 hello-world 都建 notebook 分 cell | 台账形式随规模缩放（Rule 9 判断优先注记） |
| 验收钳制 | 视觉门/数字门当橡皮章，明知图不对也放行 | 门的目的是发现问题——发现问题就该改 |
